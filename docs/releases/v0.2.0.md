## Merx v0.2.0 — Capability Feed and extensible payments

This release connects agent-oriented product discovery with an extensible payment layer and a public project website.

### Try it

- [Project website and interactive examples](https://kamilkubik89.github.io/merx/)
- [Build the agentic commerce community with us](https://kamilkubik89.github.io/merx/agentic-commerce.html)
- [Product feeds for AI agents](https://kamilkubik89.github.io/merx/product-feeds-for-ai-agents.html)

```bash
git clone --branch v0.2.0 https://github.com/kamilkubik89/merx.git
cd merx
npm run demo
npm run demo:feed
```

Node.js 22.6+ required. Neither demo needs dependency installation, an API key or a model subscription.

### Capability Feed — experimental format

- Signed packets bound to the buyer's request hash.
- Stable product facts cached by SHA-256 revision, with fresh indicative offers on each request.
- Suitability reasons, evidence references, missing context and actionable operation hints.
- `discover_offers` over MCP/A2A and `POST /v1/discover` over REST.

### Payment integration

- Multiple registered providers with discoverable currency, country and protocol metadata.
- Provider selection included in the signed quote.
- Stable order idempotency keys and server-side recovery after payment-setup failures.
- An injectable hosted-checkout factory for integrating official provider SDKs.

### Community and quality

- Responsive project website with engine-generated examples, FAQ, community copy and search/social metadata.
- Contribution guidance, launch drafts, Codespaces configuration and integration documentation.
- 42 tests passing locally, with 98.81% line coverage at release preparation.
- Fix for the previous catalog-linter regular-expression escaping finding.

### Compatibility and limits

The bulk feed and existing commerce transports remain available. The legacy single `payment` option still works; new applications can use `payments` and `defaultPaymentMethod`. Manifest payment IDs remain under `payment_methods`; descriptors are under `payment_handlers`.

Quotes now include `payment_method`. Orders can report `payment_pending` or `payment_setup_failed`; clients must not assume every accepted order already has payment instructions. A trusted backend retries setup with the original order ID.

Merx remains an in-memory reference implementation. The bundled bank-transfer provider is fictional and does not settle payments. Stripe, PayPal, AP2, ACP, UCP and x402 integrations are not bundled. Capability Feed is a Merx experiment, not an industry standard. Evidence references are not independently verified, and indicative offers require a fresh quote. Production authentication, trusted wallet identity, durable recovery and verified settlement remain deployment work.
